## 项目是什么

2026 夏季学期《基于 Agent 的应用系统开发》课程设计（清华大学经济管理学院，毛波老师）。我和 10 人团队（第一组）一起，从零搭建了一套**舆情监测与智能研判 Agent 系统**，成品名叫「清舆智析」。

- **项目周期**：6.21 ~ 7.19，集中四周，全程无休
- **团队节奏**：每天一次 Scrum + 隔天一次线下大讨论（大多在李华 457）
- **选题**：面向中文社交媒体（尤其是清华内部信息平台、云上校友圈、新清华树洞这类校内场景）的舆情监测与研判
- **目标**：打通「自动采集 → 情感分析 → 时序分析 → 预警研判」全流程，让整个监测流程无人值守地持续运转

系统对外有两个入口：

- **Web Dashboard**：11 个功能页面，负责看板、词云、趋势、平台对比、预警清单等
- **对话式舆情助手**：用自然语言提问，Agent 自己决定调哪些工具、拿什么证据、怎么给结论

## 系统架构

整体分五层，层与层之间解耦，每一层都可以独立开发、独立测试：

- **数据采集层**：五个平台的独立爬虫 + 一个统一调度器，采集后自动触发情感标注
- **数据存储层**：PostgreSQL 16，1 张核心内容表 + 4 张时序分析表
- **后端服务层**：FastAPI 提供 REST 与 WebSocket，内部挂 LangChain Agent（13 个工具）和定时调度微服务
- **前端展示层**：React 18 + TypeScript，11 个页面
- **运维层**：Docker Compose 容器化，GitHub Actions 做 CI

## 五个技术模块

### 1. 数据采集：五个平台，一个调度器

<img src="/images/ps-crawler.png" alt="数据爬取架构" style="border-radius: 12px; border: 2px solid #000; box-shadow: 5px 5px 0 #A8D5E2;">

*图 2｜数据采集层：调度器统一编排五个平台的爬虫*

- **B站爬虫**基于 `bilibili-api` 异步库，通过 `asyncpg` 直写数据库，支持「热门视频」和「关键词搜索」两种模式，采集视频最近 24 小时内的评论并拼接成 content 字段
- **云上校友圈爬虫**调用微信小程序接口，只取距爬取时刻 24 小时内的增量帖子；评论不足时以帖子正文作为 content
- **贴吧、知乎、新清华树洞**分别通过浏览器自动化和平台接口补充社区讨论数据

调度器 `run_all_crawler.py` 统一管理各平台爬虫，依次运行，采集完成后自动触发情感标注脚本，形成「采集即入库、入库即分析」的流水线。所有爬虫都采用增量时间窗口，内置随机延迟、批次休眠和最大重试次数等反爬策略，保证长期运行的稳定性。

### 2. 情感分析：两个引擎各干各的

<img src="/images/ps-sentiment.png" alt="情感分析架构" style="border-radius: 12px; border: 2px solid #000; box-shadow: 5px 5px 0 #A8D5E2;">

*图 3｜情感分析的两个引擎：自动打分的 BERT，和按需推理的 Agent*

- **引擎一（自动）**：爬取数据入库后立即跑 DistilBERT 多语言情感模型，输出 Direction（正面 / 中性 / 负面）与 Score（置信度），直接写进库
- **引擎二（按需）**：jieba TF-IDF 分词并提取关键词，服务于 Agent 的检索、关键词追踪、时序分析等总结性功能

这里有个刻意的取舍：大批量的初筛交给本地模型和分词来做，LLM 只用来处理真正需要判断的部分。在舆情监测这种对实时性敏感的任务里，这一步省下的是实打实的费用和时间。

入库的「关键词—得分」向量最终收敛成 10 个字段：

```
id, author, title, content, time, platform,
direction(情感方向), score(置信度), keyword, parent_keyword
```

其中 **title / content 双级关键词**的设计值得一提。我们把每个平台的内容拆成两层：title 是母内容（B站的标题、贴吧的帖子主内容），content 是子内容（评论、回复）。对 title 和 content 分别提关键词，再把 content 与所属 title 拼在一起做情感打分。举个例子：帖子标题是「评价一下清华的食堂好不好吃」，下面两条评论分别是「清华的食堂非常难吃」和「好吃」。如果只对评论单独提关键词，第二条评论里根本没有「清华」这个词，检索「清华」时就永远漏掉它。拼上母话题之后，两条评论都能被准确召回。

### 3. Agent 语义研判层

<img src="/images/ps-agent.png" alt="Agent 语义研判架构" style="border-radius: 12px; border: 2px solid #000; box-shadow: 5px 5px 0 #A8D5E2;">

*图 4｜Agent 工作流：收集证据 → LLM 综合研判 → 规则兜底*

研判层基于 LangChain ReAct 与 LangGraph 构建，共封装 **13 个工具**，覆盖系统总览、信号检索、时序分析、规则预警、预警流水线、关键词追踪与外部搜索等能力：

- 数据检索类：`system_overview`（整体态势）、`retrieve_analysis`（关键词查文章）、`read_articles`（读具体内容）、`get_alert_details`（预警详情）、`read_signal_records`（信号原始记录）
- 时序类：`time_series`（趋势分析）、`time_series_targets`（跟踪目标）
- 预警类：`rule_engine`（规则预警判断）、`stage_alert`（多关键词分组预警流水线）
- 外部与上下文：`web_search`（外部查证）、`system_context`（数据新鲜度等）

几个设计上的坚持：

- **证据有优先级**：本地原文 > 本地可复核统计 > 系统输出 > 外部信息 > Agent 推断。推理可以补位，但不能越过证据。
- **结构化契约**：工具之间传递的是 Pydantic 定义的 schema（`AlertReviewResult`、`EvidenceEnvelope` 等），不是自由文本，避免「一段话说得挺像那么回事」的幻觉结论。
- **规则兜底**：确定性逻辑覆盖一部分结论，例如只有单条帖子时自动降级，样本不足时收窄结论范围。
- **成本控制**：Agent 实例按 Skill 缓存复用、按任务动态装载工具，能力完整的前提下少花冤枉钱。

### 4. 预警：规则引擎 + 预警流水线

预警模块由两部分组成。`rule_engine.py` 负责计算基线与分级评估，输出红、橙、黄三级预警，所有阈值与词典走配置中心，运营人员在前端「系统设置」里就能实时调整；`stage_alert.py` 把与关键词相关的所有文章按 parent_keyword 分组，逐组评估等级，最后输出全局综合研判结论。两者共享同一套核心逻辑，可以被 Agent 工具或 API 层独立调用。

我们坚持「高召回、不合并」：每个来源保留自己的观察对象、窗口、阈值、等级和证据，来源信号之间可以互相印证，但不用简单加权、投票或平均去合成一个事件结论；单个来源信号也能独立进入展示和研判。同时，**来源信号、对象状态、事件等级、证据置信度**这四个维度严格分离——「高优先级 + 低置信度」是完全合法的状态：疑似人身安全的事件哪怕只有一条帖子也需要立刻核验，但它不会被表述成「事件已经证实」。

## 踩过的坑

1. **GitHub 管理**：所有成员都是 Collaborator 的时候，需要专人维护版本。我们中间经历过一次彻底重构，起因就是无数个文件夹套文件夹和叫不出名字的文件。
2. **数据库直连 vs CSV**：早期爬虫直连和 CSV 读取混用，字段不一致埋了不少雷。后来统一到服务器上的数据库，字段约束才稳定下来。
3. **时区**：UTC 与 CST 混用，导致「刚刚聊完的窗口显示成 8 小时前」。统一走北京时间之后才消停。
4. **爬虫稳定性**：平台一更新就可能失效，新清华树洞的 token 还需要定期维护。
5. **服务器环境**：venv、Docker 镜像源、校内网络，每一样都拦过我们一阵子。
6. **vibe coding 的边界**：用 AI 写代码效率很高，但每次动工前先让 Agent 看一遍现状、写完自己再读一遍，这两步省不得。

## 写在最后

这是我第一次以 PM 身份带一个完整项目。从需求拆解、分工、技术选型到进度追踪，每一步都是新的学习；也是第一次完整地经历「从需求到交付」的整个软件开发过程。

技术上最大的收获是理解了 Agent 系统的一种可行形态：**把 LLM 当作推理引擎，围绕它搭一圈工具，让 Agent 自己去编排流程。** 数据进来了，它自己决定要不要分析、要不要预警、用什么格式输出。而要让这套东西真的可用，靠的还是前面那些不起眼的活儿——清晰的表结构、可靠的数据源、可复核的证据链。

作为 PM，另一份收获来自团队。项目初期节奏比较依赖我推进，到后半程，大家各自有了想法来推动项目往前走，我也能松一口气。隔天一次的线下讨论，解决了很多一个人闷头搞不定的问题——数据库的建立、项目部署到服务器，都是大家坐在一起聊出来的。

项目已经结束，感谢同学们夜以继日的合作，也感谢毛老师每天看我们的进度汇总。来日当与诸君共勉。

**后续可能的改进方向**：Agent 工具扩充（报告导出 PDF / Word / Excel、定时自动研判）、多 Agent 协作、爬虫稳健性维护、以及用 Neo4j 做知识图谱支持事件脉络追踪。
